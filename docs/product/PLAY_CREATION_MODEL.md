# 游创产品 Profile

> [English](./PLAY_CREATION_MODEL.en.md) · [中文](./PLAY_CREATION_MODEL.md)

游创（play-creation）是 Yggdrasil 可以承载的一类强观点产品形态：使用者既能体验作品，也能审视、修改、fork、组合并继续创作。

本文定义当前官方游创 Profile 的产品语言和 Surface 协作方式。它不是 Yggdrasil 整个平台的唯一产品立场，不要求其他应用、服务、工具或发行版采用 Project、Play、Forge 或 Assist。

平台的总体产品模型见 [`PLATFORM_PRODUCT_MODEL.md`](PLATFORM_PRODUCT_MODEL.md)。

## 游创前提

许多创作工具把人严格分成成品的消费者和工具的开发者。游创 Profile 让这两个行为形成连续谱：

- 使用者可以启动作品、观察状态、保存、fork、替换组件并提出修改；
- 创作者可以用同一份公开协议调试、组合、扩展和发布；
- AI 辅助与人工编辑都走明确身份、权限、变更和审批边界；
- 进入更深的创作能力不需要切换到一个拥有平台私有权限的“开发者版本”。

## 当前 Profile 的 Surface

这些 slot 属于当前 Shell Profile 和 Contract V1 兼容面，不属于宪法基底。未来 Shell 可以采用不同 slot 或不同交互结构。

### Home / Play

Home 发现并启动当前发行版能够管理的作品或项目；Play 承载作品自己的主要 Surface。平台负责导航、权限和 Host 连接，作品负责自己的视觉与领域语义。

### Forge / Workbench

Forge 是面向深度创作与检查的工作区。事件、组件、对象、分支、变更、权限和诊断可以在这里被观察；领域编辑器由组件或 Surface 提供，而不是由内核硬编码。

### Assist

Assist 是上下文辅助入口。它可以解释状态、提出建议、起草受控变更或调用已授权能力，但不是特权修改路径。第三方 assistant、人工工具或自动化组件可以替换它。

## 典型游创循环

```text
发现作品
→ 启动并使用
→ 观察状态与历史
→ 提出修改或 fork
→ 人工或 AI 工具产生候选变更
→ 审阅与授权
→ 应用到新分支或当前作品
→ 比较、保留、分享或继续创作
```

具体产品可以省略、扩展或重新排列这些步骤。平台只提供所需的通用身份、权力、对象、历史、调用和 Host 能力；作品语义由采用的协议与组件拥有。

## Profile 提供的默认观点

游创 Profile 倾向于：

- 历史可查看，重要改变可追溯；
- 修改前保留分支或可恢复点；
- 使用者可以替换组件而不失去作品；
- Surface 与创作工具可由第三方贡献；
- AI 输出是候选工作，不自动获得无限权威；
- 分享包含内容、依赖、兼容和迁移信息，而不只是一张截图或一个在线链接。

这些观点约束选择该 Profile 的产品，不约束其他 Yggdrasil 产品。

## 与其他产品形态共存

一个纯文档工具、普通 Web 服务、IDE、自动化系统、多人世界或无头 agent runtime 可以完全不采用游创 Profile。它们仍可共享 Yggdrasil 的身份、权限、对象、调用、组件、Host 和协议演进能力。

同样，YdlTavern、世界模拟、外部游戏引擎和其他体验可以采用游创 Profile 的全部、部分或自己的替代协议。官方实现没有隐式优先级。

## 建设边界

游创需求可以暴露平台缺少的通用能力，但不能直接把以下概念下沉为宪法基底：

- 玩家、角色、消息、回合、世界、场景或游戏规则；
- Home、Play、Forge、Assist 或具体编辑器；
- 一种固定的 proposal、branch 或发布工作流；
- 官方组件 ID、默认模型或特定 UI 状态。

只有经过泛化、明确所属层，并对其他产品也有独立价值的机制，才进入更低层。

## 当前实现

当前官方发行版、能力包和模板已经提供一部分游创体验。它们是产品能力，不是平台完整性的唯一衡量。具体状态见 [`../ALPHA_STATUS.md`](../ALPHA_STATUS.md)。
